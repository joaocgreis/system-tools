QAC / date tools

One calendar day.
Three characters.

cdate encodes dates from 2000 through 2061. ddate decodes them and uses your installed date command to format the result. TypeScript executables live in impl_ts/; native Rust binaries are built from impl_rust/. Both use the same interface. This offline guide explains their common behavior using TypeScript code excerpts. Terminal examples assume the commands are installed on PATH.

Try the encoding

A1B
2010-01-11 encodes as A1B.
A1B decodes as 2010-01-11.

Year index 10 gives A. Month 1 gives 1. Day 11 gives B. Uppercase A and lowercase a describe different years.

This calculator simulates the calendar encoding only. It does not run a command, parse timestamps, access files, or make network requests.

Step 1 / encoding

The alphabet defines the range

Each position stores its own field using 0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz. The year index is the year minus 2000; months and days use their ordinary numbers. With 62 year characters, the final year is 2061.

The minimum code is 011 and the maximum is zCV. Years outside the range cause an error. The year never wraps into an earlier century.
Step 2 / arguments

Parse every argument and reject conflicts

The TypeScript implementation uses Node's parseArgs; Rust uses lexopt. Both recognize options and positional words. Strict mode rejects unknown flags. Tokens preserve duplicate occurrences, including aliases such as -u and --utc. Each time-zone group accepts one option. An input-zone option and an output-zone option can be combined; conflicting options within a group fail.

-h and --help return before operational file access, subprocesses, and log creation. The terminal below includes the actual authored help text for both commands.

-d means debug. Use the long-only --date option to supply an input. For ddate, attach optional ISO precision as -Iseconds or --iso-8601=seconds.
Step 3 / input and files

Reject impossible calendar fields

Numeric dates are checked before the system parser sees them. Leap-year rules determine the month length, so February 30 cannot silently become a March date. Named English dates and relative expressions go through the installed parser. JavaScript parsing is opt-in and follows independent validation.

cdate --reference FILE reads only file metadata and encodes its modification date. The commands have no credentials or HTTP contract. No API fields, provider limits, authorization headers, or cookies are collected.

When both fields can be months, automatic year-last numeric input uses month/day order. Select -i dmy or -i mdy when the order matters.
Step 4 / system parser

Interpret input, then select the output day

Input and output zones independently default to UTC. --input-local, --input-utc, or --input-timezone selects the zone for unzoned input. --local, --utc, or --timezone selects the output zone only. An explicit input offset identifies an instant regardless of input flags. That instant is converted to the output zone before encoding. Subprocess arguments go directly to date, without shell interpolation.

With TZ=America/Los_Angeles, 2010-01-11 means UTC midnight by default. --local encodes that instant as January 10 locally. --input-local --local instead uses local midnight and encodes January 11. In -i javascript mode, ISO date-only strings always mean UTC; input flags affect unzoned date-times.

Each subprocess has a five-second timeout. Unzoned absolute clock input must round-trip in the input zone without an adjustment, which catches missing local times during a DST change.

Step 5 / decoding

Three valid characters must also make a valid date

ddate checks the code's length and alphabet, then validates month and day indexes. It applies the same Gregorian leap-year rule. A year character can be lowercase, but month and day indexes never reach the lowercase part of the alphabet.

A2T is invalid because 2010 was not a leap year. C2T is valid and decodes to 2012-02-29.
Step 6 / output

Assign midnight, then display it in the output zone

The three-character code contains no time or original zone. ddate can take a zone with the code, such as A1B Asia/Tokyo or A1B+05:30. An explicit input flag overrides that zone and assigns midnight to the same calendar day in the requested zone. Otherwise the supplied zone is used, or UTC if none is supplied. The verified instant is then formatted in the independent output zone with date.

ddate A1B+05:30 '+%F %T %z' displays 2010-01-10 18:30:00 +0000. Add --input-utc to reinterpret January 11 as UTC midnight and display 2010-01-11 00:00:00 +0000. Output flags change display only; %s stays the same. A missing midnight fails in the input zone.

Normal stdout contains only the primary result. Errors and the log-path announcement use stderr. TypeScript awaits each standard-stream write callback. Rust checks each write and flushes the stream before returning.

Step 7 / failures and debug

Keep diagnostics in a private log

-d or --debug creates _YYYYMMDD_HHMMSS_SCRIPTNAME.log in the current directory, using local time and the executable basename. Exclusive creation and mode 0600 protect an existing log from replacement and restrict its permissions.

The log records the plan, steps, findings, reasons for subsequent actions, validation, completion, and failures with causes. These tools perform no HTTP requests. Logs contain supplied date strings, paths, or formatting expressions and should be handled as private data.

Invalid input and unexpected errors exit with status 1. A failure while recording another failure is reported too. A late log or output failure can follow a printed result, so callers must check exit status.
Step 8 / runtime and verification

Build or run either implementation, then check both

The extensionless files in impl_ts/ start with a shell/TypeScript bootstrap. The shell redirects the same source file to Node's stdin, forwards "$@", and replaces itself using exec. STANDALONE_SCRIPT_NAME preserves the real command name. The remaining comments document maintainer requirements.

Node.js 22.18+ strips erasable TypeScript syntax using --input-type=module-typescript. Runtime execution does not typecheck. The skill's bundled checker uses a private temporary .ts copy because the compiler requires a recognized suffix. Both TypeScript commands must pass that strict check after edits. Rust builds two native binaries with a size-optimized release profile and no Node.js runtime dependency. tests/run-tests.sh checks TypeScript, Rust formatting and linting, both language unit suites, and common CLI behavior for both implementations.

Both language unit suites check all 22,646 valid calendar days and all 238,328 three-character codes. The shared behavior suite checks parser, formatting, zone, error, help, reference, and logging paths for each implementation. ShellCheck applies to an extracted shell bootstrap, while the complete file is checked as TypeScript.
